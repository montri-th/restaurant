# ตรวจ spatial join ร้านอาหาร × อาคาร/พื้นที่ของชุดข้อมูลกลุ่ม Land — 28 ตุลาคม 2569

คำขอของเจ้าของ (28 ต.ค. 2569): “ฝากเช็ค spatial join กับ อาคาร/พื้นที่ ใน dataset กลุ่ม Land ใน registry sheet ด้วยนะ” และ “รูปทรงอาคารถ้ามี LOD > 1 … ให้ใช้ที่ละเอียดกว่าแทน” · สคริปต์ `scripts/build-land.py` · หลักฐานเครื่องอ่าน [land-join-check.json](land-join-check.json) · ป้ายหลักฐานตาม MBB v0.5.3 §3.7

## สรุป

**Observed fact**

- ทะเบียนกลุ่ม Land (R11) มี 4 ชุดที่มีลิงก์ `host_context_enrichment` ไปร้านอาหาร (R12, สถานะ idea / pending_research): ศูนย์การค้าและสถานที่ค้าปลีก `DL-fdc869a77aca940153dd` · อาคารสำนักงาน `DL-8e308daca1bf455d9375` · โรงแรม `DL-845a42d1d4c939aa2590` · นิคมอุตสาหกรรม `DL-2669875b0346b95e63be` ทั้งสามลิงก์แรกถามให้ **แยกร้านภายในออกจากบริเวณรอบ ๆ** — การตรวจนี้ทำตามนั้น
- ใน 7 จังหวัดที่ข้อมูลร้านครอบคลุม มี host ใน Land 5,906 แห่ง (ศูนย์การค้าและสถานที่ค้าปลีก 3,262 · โรงแรม 2,266 · อาคารสำนักงาน 378) และหาอาคารที่จุดของ host ได้ 4,030 แห่ง (68%)
- จุดของร้าน 70,214 จุด: **1,882 จุดตกในอาคาร Land** และอีก 932 จุดติดขอบ (≤ 10 ม.) · สาขาในทะเบียนร้านเครือที่มีจุดใน 7 จังหวัด 7,630 จุด: 1,741 จุดตกในอาคาร และ 389 จุดติดขอบ
- host ที่มีร้านหรือสาขาจุดตกในหรือติดขอบอาคาร 1,478 แห่งใน 1,399 อาคาร — ศูนย์การค้า 108 จาก 124 แห่ง · คอมมูนิตี้มอลล์ 24 จาก 35 · โรงแรม 340 จาก 2,266 · อาคารสำนักงาน 147 จาก 378
- รูปทรงละเอียด (LOD2: ส่วนอาคารที่มีฐานและยอดของตัวเอง) ใช้แทน LOD1 ใน 18 อาคาร (93 ส่วนอาคาร) ตามคำสั่งเจ้าของ
- ลิงก์จากชื่อร้านไปศูนย์การค้าที่ชีตวิจัยบันทึกไว้ 1,568 ลิงก์: จุดของร้านอยู่ในอาคารของศูนย์นั้น 780 (50%) ติดขอบ 87 และห่างไม่เกิน 100 ม. 161 — รวม 1,028 ลิงก์ (66%) สอดคล้องกับตำแหน่ง; 369 ลิงก์ชี้ไป host ที่ยังหาอาคารไม่ได้

**Inference**

- การจับจุดกับอาคารใช้แยก “ในอาคาร” กับ “รอบอาคาร” ได้ดีสำหรับศูนย์การค้าและอาคารสำนักงาน แต่ใช้ไม่ได้กับตลาด ตลาดนัด และปั๊มน้ำมันส่วนใหญ่ เพราะจุดของสถานที่ไม่ได้อยู่ในอาคาร (1,112 แห่งไม่มีอาคารที่จุด)
- ลิงก์ชื่อที่ไม่สอดคล้องส่วนใหญ่มาจากอาคารซ้อนกัน (ซูเปอร์มาร์เก็ตหรืออาคารสำนักงานภายในศูนย์) และจุดแสดงผลที่ละเอียด 9.55 ม. — การตรวจนี้นับจุดที่อยู่ในอาคารซ้อนให้ทุกอาคารที่ครอบจุด (100 จุดร้าน · 182 จุดสาขา) ลิงก์ที่ยังขัดกันเหลือ 18 รายการให้ทีมวิจัยตรวจ (`nameLinkReview`)

**Recommendation**

- ใช้ผลนี้ในเว็บเป็น display-time candidate (“จุดตกในอาคาร” ไม่ใช่ “ตั้งอยู่ใน”) ตามที่ทำในรุ่น 0.3 แล้ว และพิจารณาเปลี่ยนสถานะลิงก์ R12 สามรายการแรกจาก idea เป็น prototype ที่มีหลักฐาน — เป็นการตัดสินใจของเจ้าของ
- นิคมอุตสาหกรรม: ยังไม่เทียบภายใน–รอบนอกตามกติกาของลิงก์ `DL-2669875b0346b95e63be` จนกว่าขอบเขต วันที่ และสิทธิ์จะผ่านการตรวจรับ (§6)

## 2. วิธี

1. **อาคารของ host** — รูปทรงที่ทะเบียนตรวจแล้วก่อน: ศูนย์การค้าใช้รูปทรงของ Shopping Center release สำหรับ `venue_id` เดียวกัน (43 แห่ง) · โรงแรมและอาคารสำนักงานใช้ `15_BUILDING_MASS` ที่ระบุ id ของตน (560 และ 6 แห่ง) · ที่เหลือใช้ footprint V4 ที่มีจุดของ host อยู่ข้างใน (เล็กที่สุด) หรือห่างขอบไม่เกิน 3 ม. — ไม่ใช้ชื่อ และไม่ใช้อาคารที่ใกล้ที่สุดเกิน 3 ม.
2. **LOD > 1 ชนะ (เจ้าของสั่ง 28 ต.ค. 2569 15:24)** — เมื่อทะเบียนมีส่วนอาคาร (ฐาน–ยอดต่อส่วน) วาดส่วนอาคารแทนก้อนเดียว และวาด footprint เป็นเส้นขอบ; การจับจุดใช้ union ของ footprint กับส่วนอาคาร — ศูนย์การค้า 9 · โรงแรม 13 · สำนักงาน 2 host (18 อาคาร 93 ส่วน)
3. **หนึ่งรูปทรง OSM = หนึ่งอาคาร** ไม่ว่าทะเบียนไหนอ้างถึง — เซ็นทรัลเวิลด์เป็นทั้งศูนย์การค้า โรงแรม (เซ็นทาราแกรนด์) และอาคารสำนักงาน 2 รายการ: รวม host เป็นอาคารเดียว และคงรูปทรงที่ละเอียดกว่า
4. **ความสัมพันธ์จุด–อาคาร** (เมตริกแบบ equirectangular ที่ 13.75° N คลาดไม่เกิน 0.5% ใน 7 จังหวัด): ในขอบอาคาร · ติดขอบ (≤ 10 ม. — อยู่ในความคลาดของจุดเอง) · รอบอาคาร (≤ 100 ม. รายงานเท่านั้น ไม่เผยแพร่รายจุด) — จุดที่อยู่ในอาคารซ้อนหลายหลังมีความสัมพันธ์กับทุกหลัง (หลังเล็กสุดเป็นหลัก)
5. **ไม่เปลี่ยนตัวเลขใด** ของร้านหรือของทะเบียน ไม่ใช่การยืนยันว่าร้านตั้งอยู่ในอาคาร อยู่ชั้นไหน หรือเป็นผู้เช่า และไม่ใช้อนุมานจำนวนพนักงานหรือผู้เข้าพัก

## 6. นิคมอุตสาหกรรม

- ทะเบียนมี 106 นิคม/เขต อยู่ใน 7 จังหวัด 22 แห่ง; ขอบเขต: พบ polygon รอยืนยันขอบเขตปัจจุบัน 57 · พบ polygon มีประเด็นต้องตรวจ 40 · ยังไม่พบ polygon 9 — **ยังไม่มีแห่งใดผ่านการตรวจรับ**
- ลิงก์ `DL-2669875b0346b95e63be` ระบุว่า polygon candidate ใช้ยืนยัน “อยู่ภายใน” ไม่ได้ และให้เทียบภายใน–รอบนอกหลังยืนยันขอบเขต วันที่ และสิทธิ์แล้ว — การตรวจนี้จึง **ไม่นับร้านในนิคม** และไม่เผยแพร่ polygon
- ตรวจได้เพียงตำแหน่งเทียบกับความครอบคลุมของข้อมูลร้าน: polygon candidate จาก tile ของ CityMETER 10 แห่ง — บางชัน ลาดกระบัง บางปู บางพลี อยู่ในแขวง/ตำบลที่มีข้อมูลร้านทั้งหมด (พร้อมเทียบเมื่อขอบเขตผ่าน) · สมุทรสาครอยู่นอกความครอบคลุม (0%) · อีก 5 แห่งอยู่นอก 7 จังหวัด

## 7. ข้อจำกัด

1. จุดของร้านเป็นตำแหน่งแสดงผลกริด 9.55 ม. และจุดของสาขาเป็นพิกัดที่ทะเบียนเลือก (locator ของแบรนด์หรือแหล่งอื่น) — จุดในอาคารข้างเคียงหรือบนถนนเป็นไปได้
2. footprint V4 เป็น LOD1 และมาจากจุดของ host อย่างเดียว ถ้าจุดของ host อยู่ในอาคารย่อย อาคารของ host จะเป็นอาคารย่อยนั้น (ตรวจได้จาก IoU ข้างบนเฉพาะ host ที่มีรูปทรงของทะเบียน)
3. host ที่ไม่มีอาคารที่จุด (ตลาด ตลาดนัด ปั๊ม ร้านในเครือขนาดเล็ก) ไม่มีผลจับ — ไม่ได้แปลว่าไม่มีร้านในสถานที่นั้น
4. ความสูงของอาคารและส่วนอาคารเป็นค่าตามแหล่ง ไม่ใช่ผลรังวัด
5. ทะเบียนร้านเครือยังไม่ครบทุกสาขา และร้านในชุดข้อมูลไม่ใช่สำมะโน — จำนวนในอาคารจึงเป็นขั้นต่ำของสิ่งที่แหล่งข้อมูลเห็น ไม่ใช่จำนวนผู้เช่า
