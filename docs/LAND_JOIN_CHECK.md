# ตรวจ spatial join ร้านอาหาร × อาคาร/พื้นที่ของชุดข้อมูลกลุ่ม Land — 28 ตุลาคม 2569 (รุ่น 0.4: อาคาร OpenStreetMap อย่างเดียว)

คำขอของเจ้าของ (28 ต.ค. 2569): “ฝากเช็ค spatial join กับ อาคาร/พื้นที่ ใน dataset กลุ่ม Land ใน registry sheet ด้วยนะ” · “รูปทรงอาคารถ้ามี LOD > 1 … ให้ใช้ที่ละเอียดกว่าแทน” · 18:27 “ใช้ OSM อย่างเดียว เหมือน web demo ของ dataset อื่น ๆ ใน registry … จุดร้านอาหารที่ตกริม ๆ ให้รวบเข้าตึกนั้นให้หมดเลย” · สคริปต์ `scripts/build-land.py` · หลักฐานเครื่องอ่าน [land-join-check.json](land-join-check.json) · ป้ายหลักฐานตาม MBB v0.5.3 §3.7

การตรวจรุ่น 0.3 (รูปทรงจากทะเบียน + footprint V4 ของ production) อยู่ในประวัติ git (`ee889a1`) — รุ่นนี้แทนที่ทั้งฉบับ

## สรุป

**Observed fact**

- ทะเบียนกลุ่ม Land (R11) มี 4 ชุดที่มีลิงก์ `host_context_enrichment` ไปร้านอาหาร (R12, สถานะ idea / pending_research): ศูนย์การค้าและสถานที่ค้าปลีก `DL-fdc869a77aca940153dd` · อาคารสำนักงาน `DL-8e308daca1bf455d9375` · โรงแรม `DL-845a42d1d4c939aa2590` · นิคมอุตสาหกรรม `DL-2669875b0346b95e63be` สามลิงก์แรกถามให้ **แยกร้านภายในออกจากบริเวณรอบ ๆ** — การตรวจนี้ทำตามนั้น
- อาคาร = รูปอาคาร OpenStreetMap จาก tile OpenFreeMap (planet 20261025_080012_pt, z14, ชั้น `building`) ชุดเดียวกับที่แผนที่วาด: ดึง 938 tiles ครอบจุด host 5,906 จุด ได้รูปอาคาร 17,819 ชิ้น รวมข้ามขอบ tile เป็น 17,690 อาคาร — ไม่ใช้ footprint V4 ของ CityMETER production อีก
- ใน 7 จังหวัดที่ข้อมูลร้านครอบคลุม มี host ใน Land 5,906 แห่ง (ศูนย์การค้าและสถานที่ค้าปลีก 3,262 · โรงแรม 2,266 · อาคารสำนักงาน 378) และหาอาคาร OpenStreetMap ที่จุดของ host ได้ 2,430 แห่ง (41%): จุดอยู่ในอาคาร 1,761 · ห่างขอบไม่เกิน 10 ม. 667 · เลือกจากรูปทรงของทะเบียนที่ซ้อนทับ 2
- จุดของร้าน 70,214 จุด: **2,239 จุดอยู่ในอาคาร Land** (ในขอบ 1,644 + ห่างขอบไม่เกิน 10 ม. 595 ซึ่งได้ตำแหน่งแสดงผลในอาคาร) · สาขาในทะเบียนร้านเครือที่มีจุดใน 7 จังหวัด 7,630 จุด: 2,038 จุดอยู่ในอาคาร (ในขอบ 1,739 + ห่างขอบ 299)
- host ที่มีร้านหรือสาขาอยู่ในอาคาร 1,036 แห่งใน 942 อาคาร — ศูนย์การค้า 109 จาก 124 แห่ง · ศูนย์การค้าชุมชน 38 จาก 60 · คอมมูนิตี้มอลล์ 21 จาก 35 · โรงแรม 219 จาก 1,663 · อาคารสำนักงาน 124 จาก 332
- รูปทรงที่ทะเบียนตรวจแล้วตรงกับรูปอาคาร OpenStreetMap ที่จุดเดียวกัน (IoU ≥ 0.5): ศูนย์การค้า 42 จาก 43 · โรงแรม 559 จาก 560 · สำนักงาน 6 จาก 6
- ส่วนอาคาร LOD2 (ฐาน–ยอดต่อส่วน จากทะเบียน) วาดในขอบ OpenStreetMap ได้ 15 อาคาร 64 ส่วน (จาก 18 host ที่ทะเบียนมีส่วนอาคาร; 3 แห่งส่วนอาคารยื่นออกนอกขอบ OpenStreetMap จึงคงเป็นก้อนเดียว)
- ลิงก์จากชื่อร้านไปศูนย์การค้าที่ชีตวิจัยบันทึกไว้ 1,568 ลิงก์: จุดของร้านอยู่ในอาคารของศูนย์นั้น 895 (57%) และห่างไม่เกิน 100 ม. 162 — รวม 1,057 ลิงก์ (67%) สอดคล้องกับตำแหน่ง; 376 ลิงก์ชี้ไป host ที่ไม่มีอาคาร OpenStreetMap ที่จุด; ลิงก์ของทะเบียนโรงแรม (`registry_branch_keys` 109) ตรงกับอาคารทั้งหมด

**Inference**

- การจับจุดกับอาคารใช้แยก “ในอาคาร” กับ “รอบอาคาร” ได้ดีสำหรับศูนย์การค้าและอาคารสำนักงาน (88% และ 37% ของ host มีร้านหรือสาขาในอาคาร) แต่ใช้ไม่ได้กับตลาด ตลาดนัด ปั๊มน้ำมัน และร้านในเครือส่วนใหญ่ เพราะจุดของสถานที่ไม่ได้อยู่ในรูปอาคาร OpenStreetMap (host 3,476 แห่งไม่มีอาคารที่จุด — มากกว่ารุ่น 0.3 ที่มี footprint V4 รองรับ 1,876 แห่ง)
- รูปอาคาร OpenStreetMap เป็นหลังเดียวกับที่ massing ของแผนที่วาด จึงไม่มีอาคารซ้อนกันอีก (ตึก Land ซ่อนรูป OpenStreetMap ของตัวเองใน massing และคงตึกที่ซ้อนอยู่ข้างใน เช่นอาคารสูงบนฐานห้าง)
- ลิงก์ชื่อที่ไม่สอดคล้องส่วนใหญ่มาจากอาคารซ้อนกันหรืออาคารข้างเคียงในโครงการเดียวกัน — ลิงก์ที่ยังขัดกันเหลือ 14 รายการให้ทีมวิจัยตรวจ (`nameLinkReview`)

**Recommendation**

- ใช้ผลนี้ในเว็บเป็น display-time candidate (“ในอาคาร” = จุดอยู่ในขอบอาคาร ไม่ใช่การยืนยันผู้เช่าหรือชั้น) และพิจารณาเปลี่ยนสถานะลิงก์ R12 สามรายการแรกจาก idea เป็น prototype ที่มีหลักฐาน — เป็นการตัดสินใจของเจ้าของ
- host ที่ไม่มีอาคาร OpenStreetMap ที่จุด (ตลาด ปั๊ม ร้านในเครือ) ต้องการรูปทรงที่ทะเบียนตรวจเองจึงจะจับได้ — เป็นงานวิจัย ไม่ใช่งานเว็บ (backlog N20)
- นิคมอุตสาหกรรม: ยังไม่เทียบภายใน–รอบนอกตามกติกาของลิงก์ `DL-2669875b0346b95e63be` จนกว่าขอบเขต วันที่ และสิทธิ์จะผ่านการตรวจรับ (§6)

## 2. วิธี

1. **อาคารของ host** — รูปอาคาร OpenStreetMap ที่มีจุดของ host อยู่ข้างใน; ถ้ามีหลายหลังซ้อนกัน (อาคารสูงที่วาดอยู่ในขอบห้าง) รูปทรงที่ทะเบียนตรวจแล้วเป็นตัวตัดสินว่าหลังไหนคืออาคารเดียวกัน (IoU ≥ 0.3) ไม่เช่นนั้นศูนย์การค้าใช้หลังใหญ่สุด โรงแรม/สำนักงานใช้หลังเล็กสุด; ไม่มีหลังที่จุด → หลังที่ใกล้ที่สุดไม่เกิน 10 ม. → หลังที่ซ้อนทับรูปทรงของทะเบียนมากที่สุด (IoU ≥ 0.3) — ไม่ใช้ชื่อ ไม่ใช้ footprint V4
2. **LOD > 1 ชนะ (เจ้าของสั่ง 15:24)** — เมื่อทะเบียนมีส่วนอาคารและรูปทรงของทะเบียนเป็นอาคารเดียวกับรูป OpenStreetMap (IoU ≥ 0.5) และส่วนอาคารอยู่ในขอบนั้น (≥ 90% ของพื้นที่) วาดส่วนอาคารในขอบ OpenStreetMap แทนก้อนเดียว — 15 อาคาร 64 ส่วน
3. **หนึ่งรูปอาคาร OpenStreetMap = หนึ่งอาคาร** ไม่ว่าทะเบียนไหนอ้างถึง — เซ็นทรัลเวิลด์เป็นทั้งศูนย์การค้าและอาคารสำนักงาน: รวม host เป็นอาคารเดียว
4. **ความสัมพันธ์จุด–อาคาร** (เมตริกแบบ equirectangular ที่ 13.75° N คลาดไม่เกิน 0.5% ใน 7 จังหวัด): ในอาคาร = ในขอบ หรือห่างขอบไม่เกิน 10 ม. (อยู่ในความคลาดของจุดเอง; จุดเหล่านี้ได้ตำแหน่งแสดงผลลึกเข้าไปในขอบ ≥ 1.5 ม. — `land.json → snaps`) · รอบอาคาร = 10–100 ม. (รายงานเท่านั้น ไม่เผยแพร่รายจุด) — จุดที่อยู่ในอาคารซ้อนหลายหลังมีความสัมพันธ์กับทุกหลัง (หลังเล็กสุดเป็นหลัก)
5. **ไม่เปลี่ยนตัวเลขใด** ของร้านหรือของทะเบียน พิกัดต้นทางยังอยู่ใน `restaurants.json` / `chains.json` และแผงแสดงพิกัดต้นทาง ไม่ใช่การยืนยันว่าร้านตั้งอยู่ในอาคาร อยู่ชั้นไหน หรือเป็นผู้เช่า

- ทะเบียนมี 106 นิคม/เขต อยู่ใน 7 จังหวัด 22 แห่ง; ขอบเขต: พบ polygon รอยืนยันขอบเขตปัจจุบัน 57 · พบ polygon มีประเด็นต้องตรวจ 40 · ยังไม่พบ polygon 9 — **ยังไม่มีแห่งใดผ่านการตรวจรับ**

## 7. ข้อจำกัด

1. จุดของร้านเป็นตำแหน่งแสดงผลกริด 9.55 ม. และจุดของสาขาเป็นพิกัดที่ทะเบียนเลือก (locator ของแบรนด์หรือแหล่งอื่น) — จุดในอาคารข้างเคียงหรือบนถนนเป็นไปได้ กติกา 10 ม. จึงรวบจุดริมขอบเข้าอาคาร แต่จุดที่ห่างกว่านั้นไม่รวบ
2. รูปอาคาร OpenStreetMap เป็นสิ่งที่ผู้ร่วมแผนที่วาดไว้ ณ วันที่ของ tile — อาคารที่ยังไม่มีคนวาด หรือวาดเป็นหลังเดียวทั้งโครงการ จะทำให้ host ไม่มีอาคาร หรือหลาย host ใช้อาคารเดียวกัน
3. host ที่ไม่มีอาคารที่จุด (ตลาด ตลาดนัด ปั๊ม ร้านในเครือขนาดเล็ก) ไม่มีผลจับ — ไม่ได้แปลว่าไม่มีร้านในสถานที่นั้น
4. ความสูงของอาคาร (render_height ของ OpenMapTiles) และส่วนอาคารเป็นค่าตามแหล่ง ไม่ใช่ผลรังวัด
5. ทะเบียนร้านเครือยังไม่ครบทุกสาขา และร้านในชุดข้อมูลไม่ใช่สำมะโน — จำนวนในอาคารจึงเป็นขั้นต่ำของสิ่งที่แหล่งข้อมูลเห็น ไม่ใช่จำนวนผู้เช่า

## 8. ไฟล์

- `data/land.json` (schema `citymeter-land-join-2`) — host ที่มีจุดในอาคาร (1,036), ความสัมพันธ์รายจุด (`snapshot`, `chains`: [key, building, 0, d]) และตำแหน่งแสดงผลของจุดที่รวบเข้าอาคาร (`snaps.rows`, `snaps.chains`)
- `data/land-buildings.geojson` — 942 อาคาร (1,006 features รวมส่วนอาคาร 64) · © OpenStreetMap contributors (ODbL) ผ่าน OpenFreeMap/OpenMapTiles · ส่วนอาคารจากทะเบียน (OSM-derived)
- `docs/land-join-check.json` — ตัวเลขทั้งหมดของรายงานนี้ + `nameLinkReview` + `hostsWithPointsByType`
- สร้างซ้ำ: `python3 -I scripts/build-land.py --osm <osm-buildings.json.gz> --shop <dump> --hotel <dump> --office <dump> --estates <dump> --ie-tiles <tiles> --lod-buildings <shoppingcenter venue-buildings.geojson> --sheet1 <dump> --chain-dump <dump> --restaurants data/restaurants.json --chains data/chains.json --areas data/areas.geojson --out . --report docs/land-join-check.json` (อินพุตภายในไม่อยู่ใน repository; `--osm` = รูปอาคารที่ถอดจาก tile OpenFreeMap ในเบราว์เซอร์ `{tiles: {"x_y": {f: [{id, k, h, b, hide, rings}]}}}`)
